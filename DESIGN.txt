## What the app does (in one sentence)

Lydia customizes a character named Lily (clothes, hair, accessories, pet) and places her in different environments to play.

---

## Core principles

- Big buttons, friendly colors, kid-appropriate
- No ads, no logins, no data collection, no external links
- Works offline once installed
- Forgiving — any combination of choices should look reasonable
- Free to host (GitHub Pages)
- Built incrementally — every session ends with a working app
- **Modular layered architecture** — every element is a separate overlay layer
- **PWA forever** — staying as a Progressive Web App, NOT submitting to the App Store

## 🏗️ THE ARCHITECTURE DECISION (most important section)

### The problem we identified

If every combination = a separate PNG file, file count grows exponentially:

| Categories supported | Files needed (variant approach) |
|---|---|
| Just hair × colors | 25 |
| + 4 tops | 100 |
| + 3 bottoms | 300 |
| + 3 shoes | 900 |
| + 5 accessories | 4,500 |
| + 3 pets | **13,500** |

This is called **combinatorial explosion**. We hit this realization in Session 2.

### The solution: Layered overlays

Every element is a separate transparent PNG, stacked at runtime:

```
Top layer:    🐶 Pet (positioned beside Lily)
              ⌚ Accessory (overlay on head/face)
              👕 Top (overlay on torso)
              👖 Bottom (overlay on legs)
              👟 Shoes (overlay on feet)
              💇 Hair (overlay on head)
Bottom layer: 👤 Base bald Lily (the canvas)
```

**Result:** ~44 files supports the same customization that would require 13,500 variant PNGs.

### What this means for already-built work

- **Hair Style currently uses full Lily variants** (long_brown, bob_brown, ponytail_brown). These work but aren't aligned with the new architecture.
- **Long-term:** refactor hair to overlays on a bald base
- **Short-term:** keep hair variants working, start NEW categories (tops, etc.) as overlays
- **Decision:** Phase 3 starts the migration to overlays. Don't refactor hair until we hit pain.

### Honest trade-offs of overlays

| Pros | Cons |
|---|---|
| 300× file efficiency | Each overlay is harder for AI to generate |
| Any combination "just works" | Each needs precise sizing/positioning |
| Adding 1 new item doesn't require regenerating others | More code complexity |
| Real character-builder architecture | Dresses are tricky (cover both torso AND legs) |

## 🛠️ The workflow (REVISED IN SESSION 2)

### Current workflow (iPad — what we used)
1. Talk to Claude in chat
2. Claude generates file
3. **Download file directly to iPad's Files app**
4. Go to `github.com/bradleywpoole-ux/play-and-build`
5. Tap "Add file" → "Upload files" → select index.html
6. Commit (replaces existing file)
7. Wait 30 seconds → refresh app on iPad

**Key insight from Session 2:** Direct file upload bypasses ALL copy-paste corruption issues (smart quotes, truncation, email mess).

### New workflow (MacBook — starting now)
Better, but still using GitHub web. Even better with Claude Code.

**Without Claude Code (browser-based):**
1. Talk to Claude in Safari/Chrome on Mac
2. Claude generates file
3. Drag file to Finder
4. Drag file to GitHub web (or use GitHub Desktop app)
5. Commit
6. App auto-updates on Lydia's iPad

**With Claude Code (future state):**
1. Tell Claude: "Add 3 more hair colors"
2. Claude reads repo, edits files, commits
3. App auto-updates on iPad
4. Done.

This is the destination workflow.

## 📐 What we've ruled out (and why)

| Idea | Why not |
|---|---|
| Photo-real characters | Breaks offline + customization |
| 3D characters | Way out of scope |
| SVG-drawn characters from scratch | **Tried it. Failed.** Looked like a "bald man." |
| App Store submission | PWA forever. No Mac/Xcode/$99 commitment. |
| Logins / accounts | Hard rule: no data collection. |
| Cloud save | Local storage only. |
| Full-variant architecture | **Decided against** — combinatorial explosion |
| Email-pasting code | **Discontinued** — smart quotes / truncation corruption |
| Textastic for code editing | **Phased out** — direct file upload is better |
| Working Copy for routine pushes | **Phased out** — GitHub web is simpler |

## ⚠️ Known reality checks

- **AI overlay generation is harder than full character generation.** Expect 2-3 tries per overlay.
- **Color matching between AI generations is imperfect.** "Pink" in one image may be slightly different in another.
- **Each new overlay needs positioning code.** First item in each category takes the most work; subsequent items reuse the position.
- **Dresses are an edge case.** They cover both torso AND legs — need special handling in the overlay system.
- **iPad-only is no longer the constraint.** MacBook unlocks much faster iteration.

## Glossary (for the beginner)

- **PWA** — Progressive Web App. Installs to home screen, acts like an app.
- **Repo** — project folder on GitHub.
- **Commit** — saving a snapshot of changes.
- **Push** — sending changes to GitHub.
- **Pull** — downloading changes from GitHub.
- **Merge** — combining two sets of changes.
- **Deploy** — making code live online.
- **Overlay** — transparent-background image stacked on top of another (e.g., hat on Lily).
- **Layered architecture** — building character from multiple stacked transparent images.
- **Combinatorial explosion** — when supporting more options means exponentially more combinations to create.
- **Variant** — a full image with one specific combination baked in.
- **Asset** — any image, sound, or file used by the app.
- **Modular** — built from interchangeable pieces.
